# PostgreSQL 로컬 개발 환경 세팅

Backend 개발자는 각자의 PC에 PostgreSQL을 설치하고 동일한 로컬 개발 DB 환경을 사용합니다.

## 공통 설정

| 항목 | 값 |
|---|---|
| Host | `localhost` |
| Port | `5432` |
| Database | `festival` |
| User | `dev` |
| Password | `1234` |

> 위 계정과 비밀번호는 로컬 개발 및 테스트 전용입니다. 실제 배포 서버에서는 별도의 계정과 강한 비밀번호를 사용합니다. 운영 DB 이름은 로컬과 동일하게 `festival`로 확정되어 있지만, 계정은 관리자용(`festival`)과 Backend 런타임용(`festival_app`)으로 분리되어 있습니다 — 자세한 내용은 `11_배포_체크리스트.md` §3-2를 참고하세요.

# 1. macOS

## PostgreSQL 설치

Homebrew가 설치되어 있다면 터미널에서 실행합니다.

```bash
brew install postgresql@18
```

설치 후 PostgreSQL을 실행합니다.

```bash
brew services start postgresql@18
```

실행 상태를 확인합니다.

```bash
brew services list
```

`postgresql@18`의 Status가 `started`이면 정상입니다.

## PostgreSQL 접속

```bash
psql postgres
```

만약 `psql: command not found`가 발생하면 PostgreSQL 실행 파일을 PATH에 추가합니다.

Apple Silicon Mac 기준:

```bash
echo 'export PATH="/opt/homebrew/opt/postgresql@18/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

다시 실행합니다.

```bash
psql postgres
```

## 개발 계정 및 DB 생성

PostgreSQL 콘솔에서 실행합니다.

```sql
CREATE USER dev WITH PASSWORD '1234';
CREATE DATABASE festival OWNER dev;
```

PostgreSQL 콘솔을 종료합니다.

```sql
\q
```

## 연결 확인

```bash
psql -h localhost -U dev -d festival
```

비밀번호:

```text
1234
```

접속 후 실행합니다.

```sql
SELECT current_database(), current_user;
```

다음과 같이 나오면 정상입니다.

```text
 current_database | current_user
------------------+-------------
 festival         | dev
```

종료:

```sql
\q
```

# 2. Windows

## PostgreSQL 설치

PostgreSQL 공식 Windows Installer를 사용하여 설치합니다.

PostgreSQL 공식 다운로드:
https://www.postgresql.org/download/windows/

설치 과정에서 다음 항목을 설치합니다.

- PostgreSQL Server
- pgAdmin 4
- Command Line Tools

Port는 기본값을 사용합니다.

```text
5432
```

설치 중 PostgreSQL 관리자 계정인 `postgres`의 비밀번호를 설정하라는 화면이 나옵니다.

이 비밀번호는 PostgreSQL 관리용이므로 기억해둡니다.

> 설치할 때 설정하는 `postgres` 관리자 비밀번호와 프로젝트에서 사용할 `dev / 1234`는 별개입니다.

## PostgreSQL 접속

설치가 끝나면 시작 메뉴에서 `SQL Shell (psql)`을 실행합니다.

다음과 같은 입력이 나타납니다.

```text
Server [localhost]:
Database [postgres]:
Port [5432]:
Username [postgres]:
Password for user postgres:
```

`Server`, `Database`, `Port`, `Username`은 기본값 그대로 Enter를 누릅니다.

Password에는 PostgreSQL 설치 과정에서 설정한 `postgres` 관리자 비밀번호를 입력합니다.

## 개발 계정 및 DB 생성

접속 후 실행합니다.

```sql
CREATE USER dev WITH PASSWORD '1234';
CREATE DATABASE festival OWNER dev;
```

종료합니다.

```sql
\q
```

## 연결 확인

SQL Shell을 다시 실행하거나 `psql`이 PATH에 등록되어 있다면 PowerShell에서 실행합니다.

```powershell
psql -h localhost -U dev -d festival
```

비밀번호:

```text
1234
```

접속 후 실행합니다.

```sql
SELECT current_database(), current_user;
```

다음과 같이 나오면 정상입니다.

```text
 current_database | current_user
------------------+-------------
 festival         | dev
```

종료:

```sql
\q
```

# 3. 프로젝트 연결

프로젝트 Backend 디렉터리로 이동합니다.

```bash
cd 2026_ANU_Festival/backend
```

`.env.example`을 참고하여 `.env` 파일을 생성합니다.

PostgreSQL 연결 정보는 다음과 같이 설정합니다.

```env
DATABASE_URL=postgresql://dev:1234@localhost:5432/festival
```

`.env`의 나머지 필수 환경변수도 `.env.example`을 참고하여 설정합니다.

> `DATABASE_URL`, `ADMIN_JWT_SECRET`, `FESTIVAL_START_AT`, `FESTIVAL_END_AT`을 포함한 여러 환경변수는 값이 비어 있거나 형식이 잘못되면 앱이 아예 시작되지 않습니다(`backend/src/config/env.validation.ts`가 부팅 시점에 검증합니다). `cp .env.example .env` 직후에는 이 값들이 비어 있으므로, 값을 채우지 않고 바로 `npm run start:dev`를 실행하면 부팅 오류가 나는 것이 정상입니다 — 당황하지 말고 `.env.example`의 안내 주석을 따라 값을 채웁니다.

> `.env`는 개인 로컬 환경 파일이므로 Git에 커밋하지 않습니다.

# 4. 세팅 완료 확인

macOS와 Windows 모두 다음 명령으로 프로젝트용 DB에 접속할 수 있어야 합니다.

```bash
psql -h localhost -U dev -d festival
```

비밀번호:

```text
1234
```

접속 후 실행합니다.

```sql
SELECT current_database(), current_user;
```

결과:

```text
festival | dev
```

여기까지 정상적으로 동작하면 PostgreSQL 로컬 개발 환경 세팅이 완료된 것입니다.

DB 스키마 변경 및 Migration 협업 규칙은 백엔드 공통 개발 문서를 따릅니다.
